# Адаптер чтения Ozon

Этап добавляет библиотеку чтения к модулю интеграций. Она не записывает каталог
или заказы в БД, не запускает синхронизацию и не добавляет списки в интерфейс.
Работающая старая панель не подключается к этому коду.
На следующем этапе поверх адаптера подключён [модуль каталога](catalog-sync.md):
именно он отвечает за сохранение карточек, очередь и интерфейс товаров.

## Доступ и использование

Входная точка для будущего процесса синхронизации — `integrations.public.Connections`.
Другие бизнес-модули используют публичные контракты этого модуля, не HTTPX,
ключи кабинета или внутренние модели интеграций.

```python
from datetime import UTC, datetime, timedelta

now = datetime.now(UTC)
with connections.reader(owner, account_id) as reader:
    for page in reader.iter_catalog():
        inspect_catalog_page(page)
    for page in reader.iter_shipments(now - timedelta(days=30), now):
        inspect_shipment_page(page)
    shipment = reader.get_shipment("59511155-0034-1")
    by_label = reader.find_shipment_by_barcode("ii50082908916")
```

`inspect_*` здесь обозначают код вызывающего приложения, не функции библиотеки.
Чтение доступно владельцу/администратору для активного кабинета Ozon. Ключи
расшифровываются внутри интеграции и не включаются в возвращаемые снимки.
Во время HTTP нет открытой транзакции или занятого соединения PostgreSQL.
Контекст закрывает HTTP-клиент и при успехе, и при исключении.

Каждый снимок и страница содержат `AccountSource`: UUID кабинета, площадку и
ревизию ключей. После успешного выхода из контекста проверяется, что кабинет
активен и ключи не сменились. Изменение названия не меняет источник.
**Это проверка актуальности чтения, не атомарная защита записи.** На этапе
синхронизации сохранение каждой порции потребует повторной проверки источника
под блокировкой кабинета в той же транзакции, которая записывает данные.

## Методы

| Операция | Метод Seller API | Назначение |
| --- | --- | --- |
| Каталог | `/v3/product/list` | Все видимости, включая архив, курсор `last_id` |
| Карточки | `/v3/product/info/list` | Подробности по ID товаров пачками до 100 |
| FBS-список | `/v4/posting/fbs/list` | Даты, статусы, курсор, до 100 отправлений на страницу |
| Отправление | `/v3/posting/fbs/get` | Текущее состояние, коды стикера, связанные отправления |
| Поиск по стикеру | `/v2/posting/fbs/get-by-barcode` | Поиск Ozon по переданному коду, включая `ii…` |

Общий транспорт также обслуживает прежнюю проверку доступа к возвратам
`/v1/returns/list`. Полной загрузки возвратов этот этап не добавляет.
В транспорте разрешён только фиксированный перечень методов чтения; методы
сборки, разделения, передачи/создания экземпляров и внешние URL отклоняются.

FBS-список по умолчанию запрашивает только «Ожидает сборки» и «Ожидает отгрузки».
`states=None` явно запрашивает все статусы. Даты должны содержать часовой пояс;
адаптер передаёт UTC. Период задаёт вызывающий код, автоматического ограничения
последними сутками/месяцем в загрузке нет. Фильтр суток применяется только в
существующей короткой проверке доступа кабинета.

## Общая модель

| Поле Ozon | Представление |
| --- | --- |
| `product_id` списка / `id` карточки | `OfferSnapshot.source_id` и ссылка `product_id` |
| `sku`, `sources[].sku` | Отдельные ссылки `sku`, не ID карточки |
| `offer_id` | Артикул и ссылка `offer_id` |
| `barcodes[]` | Точные строки кодов товара, включая ведущие нули и `OZN` |
| `posting_number` | `ShipmentSnapshot.source_id` и основная ссылка отправления |
| `order_id`, `order_number` | Отдельные ссылки заказа, только если переданы Ozon |
| `tracking_number`, `scanit`, `barcodes` | Дополнительные ссылки отправления, в том числе `ii…` |
| `products[].sku` | Идентификатор строки отправления и ссылка на SKU каталога |
| `parent_posting_number`, `related_postings` | Явный родитель и отдельно связанные отправления |
| `multi_box_qty` | Только подсказка количества мест; не список грузомест |

Сопоставление выполняется в пределах кабинета и типа ссылки. Номер заказа
не вычисляется обрезанием номера отправления. Первая связанная посылка не
объявляется родителем. Разные SKU одной карточки сохраняются отдельно.
Деньги представлены `Decimal`, количества — положительными целыми числами.

Коды товара не дополняются и не обрезаются. `gtin` — классификация по цифровому
формату и длине, **не проверка контрольной цифры и не подтверждение соответствия
Честному знаку**. Распознавание полного DataMatrix сюда не входит.

Обычные снимки не содержат покупателя, телефона, адреса, API-ключей, исходного
JSON или полных кодов маркировки из устаревшего `mandatory_mark`. Время наблюдения
записывается отдельно и не участвует в сравнении содержимого снимков.

Отсутствующие поля не превращаются в отрицательные ответы: нет признака архива —
`archived=None`; нет цены — `unit_price=None`. `fields_present` указывает, какие
поля наблюдались. Укороченный ответ поиска по стикеру не позволяет очищать ранее
загруженные коды или требования. Будущий обработчик БД должен учитывать это,
а не заменять полную запись всеми пустыми значениями снимка.

`requirements.products_requiring_*` и
`optional.products_with_possible_mandatory_mark` сохраняются как положительные
подсказки `required_fields` / `optional_fields` по строкам. **Пустые массивы не
подтверждают отсутствие требований. `requirements_complete` всегда `False`.**
Проверка `is_mandatory_mark_needed`, `is_mandatory_mark_possible`, `is_gtd_needed`
через экземпляры и правила обязательности нашей панели переносится отдельно
в сборку. Из этого адаптера нельзя сделать вывод, что заказ можно собрать без ЧЗ.

Сырой статус и подстатус сохраняются вместе с общим состоянием. Неизвестный
статус становится `unknown`; `ship_failed` не считается готовностью к отгрузке.
Адаптер ничего не переводит в другой статус и не освобождает привязки ЧЗ.

## Неполные загрузки и ошибки

Страницы читаются лениво. Каталог загружает детали только текущей страницы;
набор всех подробных карточек/заказов не накапливается в памяти адаптера.
ID и курсоры текущего прохода хранятся для обнаружения повторов. По умолчанию
проход ограничен 200 страницами; размер/предел можно настроить в адаптере.

Пропущенные, дублированные или неожиданные ID подробных карточек не выдаются как
успешная страница. Повтор ID/курсора, цикл, `has_next` без следующего курсора,
пустая промежуточная страница или достижение предела страниц прерывают проход.
`total`/`total_items` — лишь подсказка, не условие завершения.
У каталога окончание определяется пустой страницей либо пустым `last_id`;
у FBS — `has_next=False`.

Уже выданные страницы не становятся полным снимком при последующем исключении.
Будущая синхронизация должна отдельно фиксировать успешное завершение прохода,
не удалять отсутствующие записи при ошибке и не считать их отменёнными.
Курсор для продолжения имеет смысл только с теми же кабинетом, ревизией ключей,
набором данных, фильтром и периодом; он не является долговечным снимком Ozon.

`ReadError` содержит безопасное сообщение, категорию, HTTP-статус и при наличии
`retry_after`. Исходные тела ошибок и тексты исключений HTTPX не возвращаются.
401/403 не повторяются; 404 даёт `None` только в точечном поиске, 400 не скрывается
как «не найдено». Таймауты, 429 и 5xx допускают до трёх попыток чтения. При длинном
`Retry-After` адаптер сразу возвращает ошибку с задержкой для будущего планировщика;
раннего повтора вопреки лимиту нет. Проверка доступа кабинета использует одну попытку.

Установлены таймауты HTTP и предел распакованного ответа 8 МиБ (проверка доступа —
128 КиБ). Перенаправления отключены. HTTP 200 с ошибкой или неверной структурой
не считается успешными данными. Неоднозначные ответы операций изменения здесь
вообще не обрабатываются, поскольку такие операции не подключены.

## Основания и проверки

Форматы сверены 21.11.2026 с опубликованным зеркалом схемы Seller API:
[vispar-tech/ozon-seller-api-schema](https://github.com/vispar-tech/ozon-seller-api-schema/blob/main/schemas/ozon-seller-api-openapi.json).
SHA-256 прочитанного файла:
`f4f387d2340e4ccfe91c48342bf6467d4e0b2b83f29424f780f732a121047897`.
Это открытое зеркало, не подтверждение вызовов с действующим ключом.

Тестовые ответы синтетические. Покрыты пагинация/пачки, соответствие ID и SKU,
точные коды, поиск `ii…`, деньги, неполные ответы, доступы, лимиты, повторные
попытки, изоляция кабинетов и отсутствие записей в бизнес-таблицы при чтении.
Реальные HTTP-вызовы в тестах запрещены; ключи рабочей панели не используются.
