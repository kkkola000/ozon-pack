# Заказы Ozon: загрузка и просмотр

Версия `2.0.0a5`, миграция `0004_orders`. Реализована загрузка FBS, сохранение
заказов/отправлений и их наблюдаемого состава, сопоставление с каталогом и
раздел «Заказы». Рабочие изменения статусов, сборка, разделение, стикеры,
передача Честного знака/ГТД и печать пока не подключены.

## Запуск

Из каталога установленной **v2** обновите зависимости/пакет, примените миграции
и перезапустите оба отдельных процесса: веб и worker. Команды установки и
обновления приведены в [README](../README.md); старая панель не переключается.

```bash
.venv/bin/python -m pack_v2 --env-file .env.v2 migrate
.venv/bin/python -m pack_v2 --env-file .env.v2 worker
```

Вторую команду запускают отдельным фоновым сервисом. Веб-процесс не начинает
синхронизацию сам. Без worker команда «Обновить заказы» остаётся в очереди.
Запускать старый корневой worker/старые deploy-скрипты для v2 не нужно.

Настройки читаются из существующего `.env.v2` либо окружения; повторное создание
ключа шифрования не требуется:

- `PACK_V2_ORDERS_SYNC_MINUTES=5` — период фонового обновления;
- `PACK_V2_ORDERS_SYNC_MINUTES=0` — только ручные команды;
- `PACK_V2_ORDERS_LOOKBACK_DAYS=30` — окно списка по дате Ozon, от 1 до 90 дней.

## Как читаются данные

Окно рассчитывается при фактическом начале каждой попытки, а не при нажатии
кнопки: долгое ожидание в очереди не оставляет загрузку на устаревших датах.
Ручной новый проход запрашивает `/v4/posting/fbs/list` за заданное окно со всеми
статусами. Первый автоматический проход тоже полный. После успешной полной
загрузки автоматические проходы в течение суток читают активные состояния:
ожидание сборки, ожидание отгрузки и доставку. Не реже раза в сутки фоновый
процесс снова планирует полный список. Это позволяет не читать всю историю
каждые пять минут. Повтор команды при активном задании возвращает его прежний ID.

После завершения списка для ранее известных незавершённых отправлений, которые
в него не попали, выполняется точечный `/v3/posting/fbs/get`. Это относится и к
старым отправлениям за пределами окна. Полученный статус сохраняется только
после положительного ответа с нужным номером и идентичностью заказа.

**Отсутствие в списке или HTTP 404 не означает отмену.** При 404 остаются
последние данные и появляется «Нужна проверка». Такие записи не входят в фильтр
подтверждённого ожидания сборки/отгрузки. Ошибка страницы прерывает проход до
сверки отсутствующих записей. Последнее успешное время не подменяется ошибочной
или незавершённой попыткой. Подтверждённый `ship_failed` не считается готовностью.

Заказы, вышедшие за окно, не удаляются. Новый уже завершённый заказ, который
никогда не попадал в панель, обнаруживается полным проходом; активный проход
не обещает полноты истории. Таймауты/лимиты обрабатываются общей очередью,
с сохранением `Retry-After` и ограничением числа попыток.

## Общая модель и сопоставление

- `Order` группирует отправления по явным идентификаторам заказа из адаптера.
  Номер не вычисляется удалением суффикса номера отправления.
- `Shipment` имеет устойчивый внутренний UUID. Основная внешняя ссылка
  `posting_number` и дополнительные номера хранятся отдельно, в пределах кабинета.
- `ShipmentItem` хранит **наблюдаемый состав конкретного отправления**: внешнюю
  строку, количество, точную цену, ссылку каталога и положительные подсказки требований.
- `OrderLine`, `OrderUnit`, `ShipmentUnit` и `Package` предназначены для следующего
  этапа сборки. Импорт не создаёт и не удаляет физические единицы или грузоместа.

Разделённые отправления сохраняются независимо. Это не позволяет повторно
сложить состав старого отправления и его новых частей в выдуманное количество
товара корневого заказа. Удалённая из состава строка остаётся с `source_present=False`
и видна в карточке как прежняя. Изменение количества не перераспределяет единицы
сборки. Количество грузомест Ozon — только подсказка, не готовый список упаковок.

Родитель определяется только явной основной ссылкой. Связанные номера не
объявляются родителями. Не загруженный родитель остаётся номером без локальной
ссылки. Циклы, ссылка на себя и родитель другого заказа блокируются.

Модуль заказов обращается к каталогу только через `catalog.public.Catalog`:
сопоставление по неизменяемому SKU/ID внутри кабинета, получение карточек и кодов.
Артикул не подменяет предоставленный, но неизвестный SKU. Одинаковые GTIN или
номера в разных кабинетах не объединяют записи. Несопоставленные позиции
сохраняются и повторно проверяются при последующих загрузках, в том числе
после более поздней загрузки каталога.

Деньги хранятся как `Numeric(18,4)` и передаются API строкой: нет преобразования
через `float`. Значение вне точности БД отклоняется, не округляется незаметно.
В интерфейсе убираются лишние нули, значащие разряды сохраняются.

Для кодов стикера сохраняется происхождение: верхний код, нижний код и `scanit`.
Пропущенное поле не очищает известный `ii…`; явно полученное пустое значение
убирает только соответствующий источник кода. Один код из двух источников
сохраняется, пока остаётся хотя бы один. Неоднозначный поиск возвращает все
совпавшие отправления, не выбирая первое автоматически.

Положительные подсказки ЧЗ/ГТД сохраняются, но обычный ответ списка не подтверждает
их полноту. `requirements_complete=False`; пустой список не снимает прежнее
положительное требование. Авторитетная проверка экземпляров и передача данных
маркету выполняются отдельным [сценарием сборки](instance-data.md).

Подтверждённые изменения статуса записываются в аудит вместе с UUID и временем
наблюдения, без кода маркировки и персональных данных. Повторное чтение того же
статуса не создаёт дублей событий. Это история наблюдений панели: первый импорт
не восстанавливает ранее пропущенные переходы и не доказывает отсутствие передачи
в доставку. Автоматическая отвязка маркировки этим модулем не выполняется.

## Надёжность и границы

`integrations.public.AccountSync` обслуживает и каталог, и заказы: создание
run/задания, повторы, аренду, ревизию ключей, прогресс и завершение. Бизнес-модуль
передаёт свою модель run, чтение и проекцию; прямого HTTP или расшифровки ключей
в заказах нет. Во время HTTP транзакции БД закрыты.

Каждая порция записывается с блокировкой кабинета, проверкой ревизии ключей,
действующей аренды и активности run. Устаревший исполнитель не публикует результат
после перехвата задания. Связи, успешный run и завершение задания фиксируются
атомарно. Уже записанные подтверждённые порции доступны и после ошибки следующей
страницы, но не объявляются полным проходом.

Чтение списков ограничено 30 отправлениями на страницу. Ссылки, позиции и карточки
подгружаются пакетами. Проверка родительских связей использует только нужные
колонки, не загружая всю историю составов. Добавлены индексы поиска и связей.
Данные покупателя, адреса, телефоны, исходные JSON и полные ЧЗ из старого поля
`mandatory_mark` не сохраняются.

## Интерфейс и API

«Заказы» показывает отправления, состав, кабинет/склад, срок и состояние.
Есть фильтры, поиск по номеру заказа/отправления, `ii…`, SKU, артикулу, названию и
точному штрихкоду сопоставленного товара. Карточка отправления содержит текущий
и прежний состав, связи отправлений и время сверки. Цвета и формы прежние.
GET страницы или поиска читает БД, не вызывает Seller API и не ставит задания.

- `GET /api/v2/orders` — `account_id`, `q`, `state`, `page`;
- `GET /api/v2/orders/{UUID}` — карточка и другие отправления заказа;
- `GET /api/v2/orders/sync` — состояние загрузок;
- `POST /api/v2/orders/sync` — JSON `{}` либо `{"account_id":"UUID"}`, HTTP 202.

Чтение требует разрешения на заказы; состояние загрузки также доступно настройкам.
Запуск — только администратору/владельцу с `X-CSRF-Token`. Доступ к товарам не
требуется для просмотра карточки товара своего отправления, но каталог целиком
по-прежнему защищён разрешением «Товары».

Тесты используют реальную PostgreSQL 17 и синтетические ответы Ozon. Браузерный
флаг `--check-orders` требует отдельного тестового сервера с MockTransport и worker;
он создаёт синтетический кабинет и проверяет загрузку, поиск `ii…`, связи и мобильную
карточку. Рабочие ключи, отправления и старую БД для проверки не используют.
