# Ozon Pack — панель сборки FBS и возвратов

Веб-панель для склада: подтягивает заказы и возвраты из Ozon Seller API и ведёт
сборщика по процессу так, чтобы он **не мог** взять не тот товар, положить его не
в то отправление или собрать одно отправление дважды.

Разворачивается на VPS, открывается по IP-адресу в браузере: `http://IP-сервера:8080`.

---

## Как устроен процесс сборки

```
  «Ожидает сборки»                    «Ожидает отгрузки»                     Готово
        │                                     │                                │
        │ 1. Кнопка «Собрать»                 │ 2. Скан штрихкода товара       │
        │    (v4/posting/fbs/ship)            │    → система сама находит      │
        │                                     │      отправление и его состав  │
        ▼                                     │    → стикер уходит на печать   │
   Заказы FBS ─────────────────────────────►  │                                │
                                              │ 3. Упаковали, наклеили стикер  │
                                              │ 4. Скан стикера отправления ───┘
```

**Что панель не даст сделать:**

| Ошибка | Как блокируется |
|---|---|
| Взяли не тот товар | Скан товара, которого нет в активном отправлении → красный экран «СТОП», товар не засчитывается |
| Положили товар не в то отправление | Закрыть отправление можно только сканом **его** стикера; чужой стикер → «СТОП» |
| Положили лишнюю штуку | Скан сверх нужного количества → предупреждение со звуком |
| Собрали дважды | Собранные отправления исчезают из подбора, повторный скан стикера → предупреждение с именем сборщика и временем |
| Двое собирают одно отправление | Отправление закрепляется за сборщиком на `CLAIM_TTL_MINUTES` минут |
| Закрыли, не собрав всё | Скан стикера до сканирования всех товаров → отказ со списком недостающего (`REQUIRE_ALL_ITEMS=1`) |

Каждое действие пишется в журнал (`/logs`): кто, что, когда, какой код отсканировал —
по нему разбираются спорные случаи.

## Разделы

### 1. Сборка (`/pack`) — рабочее место сканера

Одно поле ввода, всегда в фокусе. Сканер работает как клавиатура — специальных
драйверов не нужно, достаточно настроить в нём суффикс **Enter** после кода.

* Скан штрихкода товара → панель показывает отправление и **весь его состав**,
  автоматически отправляет стикер на печать.
* Если товар нужен в нескольких отправлениях — показывается список, отсортированный
  по сроку отгрузки (выбор мышкой или цифрой 1–9 на клавиатуре).
* Прогресс «собрано N из M», у каждой позиции — артикул, SKU, штрихкоды, отметка
  «Честный знак».
* Скан стикера отправления закрывает сборку. Звуковые сигналы: успех, предупреждение, ошибка.
* Кнопка «Завершить без скана стикера» — на случай нечитаемого стикера (попадает в журнал).

Понимаются коды: EAN-13/UPC (в том числе с ведущим нулём), SKU и артикул продавца,
DataMatrix «Честного знака» (из него извлекается GTIN), номер отправления,
штрихкоды стикера Ozon (`upper_barcode` / `lower_barcode`), а если код неизвестен
локально — панель спрашивает Ozon через `v2/posting/fbs/get-by-barcode`.

### 2. Заказы FBS (`/orders`)

Вкладки «Ожидает сборки» / «Ожидает отгрузки» / «Собранные». Массовые действия:
перевести выбранные в «Ожидает отгрузки» (`v4/posting/fbs/ship`) и напечатать пачку стикеров.
По каждому отправлению: срок отгрузки с подсветкой просрочки, состав, город и регион,
способ доставки и служба, склад, тип оплаты, метки Express / маркировка / многоместное,
кто сейчас собирает, печатался ли стикер.

### 3. Возвраты FBO/FBS (`/returns`)

Единый список возвратов обеих схем (`v1/returns/list`) с фильтрами по схеме,
пункту выдачи и поиском. Кнопка **«Печать листа»** формирует лист А4 со штрихкодами
Code128, колонкой для отметки и полями для подписей — с ним сборщик идёт получать
возвраты. Полученные позиции отмечаются кнопкой «Отметить забранными».

Возврат считается готовым к выдаче, если его статус входит в `RETURNS_READY_STATUSES`
(по умолчанию `ArrivedAtReturnPlace`, `WaitingShipment`) либо у него проставлена дата
прибытия в пункт выдачи.

### 4. Журнал (`/logs`) и Настройки (`/settings`)

Журнал сканов и действий с фильтрами. Настройки: состояние синхронизации, проверка
ключей Ozon, управление сотрудниками (роли «администратор» и «сборщик»).

## Быстрый старт (демо, без ключей Ozon)

```bash
git clone https://github.com/kkkola000/ozon-pack.git && cd ozon-pack
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env
echo "OZON_DEMO=1" >> .env
echo "ADMIN_PASSWORD=admin123" >> .env
.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8080
```

Откройте `http://localhost:8080`, войдите как `admin` / `admin123`. В демо-режиме
данные генерируются локально — можно прогнать весь процесс сборки, не трогая Ozon.

## Развёртывание на VPS

### Вариант A. Docker (рекомендуемый)

```bash
git clone https://github.com/kkkola000/ozon-pack.git /opt/ozon-pack
cd /opt/ozon-pack
cp .env.example .env
nano .env                 # впишите OZON_CLIENT_ID, OZON_API_KEY, ADMIN_PASSWORD
mkdir -p data && chown -R 10001:10001 data   # контейнер работает под непривилегированным uid
docker compose up -d --build
docker compose logs -f    # здесь виден пароль администратора, если он не задан
ufw allow 8080/tcp
```

Панель: `http://IP-сервера:8080`.

### Вариант B. Без Docker (systemd)

```bash
git clone https://github.com/kkkola000/ozon-pack.git && cd ozon-pack
sudo ./deploy/install.sh          # venv + служба + правило файрвола
sudo nano /opt/ozon-pack/.env     # ключи Ozon
sudo systemctl restart ozon-pack
sudo journalctl -u ozon-pack -f
```

Чтобы открыть панель на 80 порту, положите `deploy/nginx.conf` в nginx
(инструкция — в первых строках файла).

### Ключи Ozon Seller API

Личный кабинет продавца → **Настройки → Seller API → Сгенерировать ключ**.
Нужны `Client-Id` и `Api-Key`; впишите их в `.env` и перезапустите сервис.
Проверить связь: **Настройки → Проверить ключи**.

## Настройки (`.env`)

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `OZON_CLIENT_ID`, `OZON_API_KEY` | — | Ключи Seller API. Без них включается демо-режим |
| `OZON_DEMO` | `0` | Работа на сгенерированных данных |
| `PORT` | `8080` | Порт панели |
| `ADMIN_LOGIN` / `ADMIN_PASSWORD` | `admin` / генерируется | Первый администратор (создаётся один раз) |
| `IP_ALLOWLIST` | пусто | Доступ только с этих адресов/подсетей, через запятую |
| `SESSION_TTL_HOURS` | `24` | Срок жизни сессии |
| `SYNC_INTERVAL` | `60` | Как часто опрашивать Ozon по отправлениям, сек |
| `SYNC_RETURNS_INTERVAL` | `300` | То же для возвратов, сек |
| `SYNC_DAYS_BACK` / `SYNC_DAYS_FORWARD` | `30` / `30` | Окно выборки отправлений |
| `REQUIRE_ALL_ITEMS` | `1` | Требовать скан каждого товара перед закрытием |
| `AUTOPRINT` | `1` | Печатать стикер сразу при выборе отправления |
| `AUTO_SHIP_ON_SCAN` | `0` | Собирать в Ozon прямо при скане (иначе — кнопкой в «Заказах») |
| `CLAIM_TTL_MINUTES` | `30` | На сколько отправление закрепляется за сборщиком |
| `TZ_OFFSET_HOURS` | `3` | Часовой пояс склада для отображения дат |
| `RETURNS_READY_STATUSES` | `ArrivedAtReturnPlace,WaitingShipment` | Статусы возвратов «готов к выдаче» |

После правки `.env` — `docker compose restart` или `systemctl restart ozon-pack`.

## Печать стикеров

Стикер приходит из Ozon в PDF и печатается **браузером сборщика** на локальный
принтер — серверу принтер не нужен. Панель открывает скрытый iframe и вызывает печать;
если браузер её блокирует, PDF открывается во вкладке.

Рекомендации: Chrome, термопринтер по умолчанию, размер бумаги 75×120 мм,
поля «нет», масштаб 100 %, отключить колонтитулы. Один раз настроенные параметры
Chrome запоминает.

## Методы Ozon Seller API

| Что | Метод |
|---|---|
| Список отправлений FBS | `POST /v3/posting/fbs/list` |
| Одно отправление | `POST /v3/posting/fbs/get` |
| Сборка (в «Ожидает отгрузки») | `POST /v4/posting/fbs/ship` |
| Стикер отправления | `POST /v2/posting/fbs/package-label` (при недоступности — `/v2/posting/fbs/package-label/create` + `/v1/posting/fbs/package-label/get`) |
| Отправление по штрихкоду | `POST /v2/posting/fbs/get-by-barcode` |
| Карточки товаров (штрихкоды) | `POST /v3/product/info/list` |
| Возвраты FBO и FBS | `POST /v1/returns/list` |
| Возвраты по пунктам выдачи | `POST /v1/returns/company/fbs/info` |
| Документ на выдачу возвратов | `POST /v1/return/giveout/get-pdf` |

Ошибки Ozon не роняют панель: запросы повторяются с нарастающей паузой,
данные хранятся локально в SQLite, последняя ошибка синхронизации видна в «Настройках».

## Безопасность

Панель по IP работает **по HTTP — трафик не шифруется**. Что стоит сделать:

* задать `IP_ALLOWLIST` (адреса склада) или закрыть порт файрволом;
* задать длинный `ADMIN_PASSWORD` и завести каждому сборщику свой логин —
  журнал ценен, только если по нему видно конкретного человека;
* если панель доступна из интернета — поднять nginx с TLS (домен + Let's Encrypt)
  или пускать сотрудников через VPN.

Встроено: пароли — PBKDF2-SHA256 (240 000 итераций), подписанные HttpOnly-сессии,
CSRF-токен на изменяющих запросах, ограничение попыток входа (10 за 5 минут).

## Обслуживание

```bash
# Резервная копия (вся история сборки — в одном файле)
sqlite3 data/ozon-pack.db ".backup '/backup/ozon-pack-$(date +%F).db'"

# Обновление
git pull && docker compose up -d --build     # или: systemctl restart ozon-pack

# Тесты
.venv/bin/python -m pytest
```

Данные лежат в `data/`: база SQLite и ключ подписи сессий. Каталог переживает
пересборку контейнера, его и нужно бэкапить.

## Ограничения

* Отметка «возврат забран» хранится только в панели: в Ozon такого статуса нет.
* Отправление собирается одной коробкой. Многоместные отправления помечаются
  меткой в интерфейсе, но разбивку по коробкам нужно делать в личном кабинете Ozon.
* Коды маркировки «Честный знак» не передаются в Ozon — панель только подсвечивает,
  что отправление их требует.
