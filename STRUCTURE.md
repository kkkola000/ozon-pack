# Структура проекта

Дерево репозитория с пояснением, за что отвечает каждый файл. Обновляйте этот
файл, когда добавляете новый модуль, — иначе он быстро разойдётся с кодом.

Правило одно: **ядро не знает площадок по именам**. Всё, что зависит от
площадки, живёт в её пакете `app/markets/<код>/` и объявляется одним объектом
`Market`. Общий код спрашивает реестр. Почему так и как сюда добавляется новая
площадка — в `ARCHITECTURE.md`.

```
ozon-pack/
├── README.md                       — полная документация: кабинеты, разделы, API площадок, установка, безопасность
├── ARCHITECTURE.md                 — устройство: ядро, площадки, реестр; как добавить площадку
├── STRUCTURE.md                    — этот файл
├── VERSION                         — номер версии сборки (виден в «Настройках» и /healthz)
├── COMMIT                          — git-хэш коммита, подставляется автоматически при `git archive`
├── requirements.txt                — зависимости для продакшена (fastapi, uvicorn, httpx, cryptography, fpdf2, pypdf…)
├── requirements-dev.txt            — requirements.txt + pytest, только для запуска тестов
├── pytest.ini                      — где лежат тесты, тихий вывод (-q)
├── ruff.toml                       — правила линтера и обоснование, почему часть выключена
├── .env.example                    — шаблон .env: ключи площадок, порт, IP-ограничения, логика сборки
├── .gitignore                      — что не попадает в репозиторий (.env, data/, *.db, кэши)
├── .gitattributes                  — COMMIT export-subst: хэш коммита подставляется при экспорте

├── app/                            — само приложение (FastAPI)

│   │
│   ├── core/                       — общий код. Площадок по именам не знает
│   │   ├── config.py               — Settings: чтение .env, порт, часовой пояс, лимиты сборки
│   │   ├── db.py                   — SQLite: общие таблицы (каталог products/product_barcodes, связи
│   │   │                             product_links), схемы площадок из реестра, автомиграции, журнал
│   │   ├── security.py             — пароли, подпись сессии в cookie, защита от подбора, CSRF
│   │   ├── crypto.py               — шифрование ключей площадок в базе
│   │   ├── access.py               — роли (владелец / администратор / сборщик) и разделы, которые роль видит
│   │   ├── accounts.py             — кабинеты: заведение, ключи, переключение; список площадок берётся из реестра
│   │   ├── deps.py                 — зависимости FastAPI: текущий пользователь и кабинет, CSRF, шаблоны
│   │   │                             (ядра + площадок через PrefixLoader), меню шапки из реестра
│   │   ├── store.py                — общие мелочи разбора: даты, числа, местное время, срочность, отметки сборщика
│   │   ├── sync.py                 — фоновая синхронизация: обходит кабинеты и зовёт market.sync(account)
│   │   ├── labels.py               — выгрузка стикеров/этикеток/ярлыков архивом и замок на сборку, пока не выгружены
│   │   ├── catalog.py              — каталог товаров: карточки, штрихкоды, обход кабинета целиком,
│   │   │                             архив. Как ходить по своему каталогу — знает площадка
│   │   ├── product_links.py        — сопоставление: карточки разных кабинетов как один товар склада;
│   │   │                             совпадения по артикулу, подтверждение, отмена, «не сопоставлять»
│   │   ├── product_sets.py         — наборы: из каких частей физически собирается товар площадки
│   │   ├── report.py               — отчёт об отгруженных товарах, выгрузка в CSV
│   │   ├── orders.py               — общий список заказов: все кабинеты в одной таблице, свой магазин
│   │   │                             сверху; плюс помощники, из которых площадки собирают свои строки
│   │   ├── return_acts.py          — акты получения возвратов: одна поездка в пункт выдачи, отметки, подтверждение
│   │   ├── returns_pdf.py          — лист возвратов файлом PDF: рамка листа, таблицу секции рисует площадка
│   │   └── version.py              — версия сборки и git-коммит для /healthz
│   │
│   ├── markets/                    — площадки. Один пакет на площадку, состав файлов одинаковый
│   │   ├── base.py                 — что площадка объявляет о себе: Market, NavItem, CatalogSource,
│   │   │                             CatalogPage, ReturnsSource, Workspace, MarketError, KeyCheckError
│   │   ├── registry.py             — реестр: единственное место, где площадки перечислены
│   │   │
│   │   ├── ozon/                   — Ozon: отправления FBS, каталог со штрихкодами, возвраты FBO/FBS
│   │   │   ├── __init__.py         — объявление площадки (MARKET): адреса, таблицы, схема, возвраты, каталог, настройки
│   │   │   ├── client.py           — клиент Seller API: отправления, товары, возвраты, стикеры
│   │   │   ├── store.py            — свои таблицы (postings, posting_items) и разбор ответов
│   │   │   ├── catalog.py          — обход каталога: список артикулов, потом карточки пачками
│   │   │   ├── sync.py             — загрузка отправлений, товаров и возвратов кабинета
│   │   │   ├── pack.py             — сборка: подбор отправления по товару, наборы, закрытие стикером, стикеры PDF
│   │   │   ├── returns.py          — возвраты целиком: таблица, статусы, загрузка, «к выдаче», акт из полученных
│   │   │   ├── routes.py           — свои разделы: /pack, /orders, API сборки и стикеров; меню и плитки настроек
│   │   │   ├── migrations.py       — разовые правки своих таблиц в старых базах
│   │   │   ├── templates/          — свои куски страниц: orders.html, returns_list/sheet/act_rows,
│   │   │   │                         pack_gate, settings_rows, settings_panel
│   │   │   └── static/             — orders.js (страница заказов), pack.js (карточка сборки на рабочем месте)
│   │   │
│   │   ├── avito/                  — Avito: заказы, сборка по этикетке, возвраты внутри заказа
│   │   │   ├── __init__.py  client.py  store.py  sync.py  pack.py  returns.py  routes.py
│   │   │   │                         (каталога у площадки нет — раздел «Товары» её кабинетам не виден)
│   │   │   ├── templates/          — orders.html, returns_list/sheet/act_rows, pack_gate
│   │   │   └── static/             — orders.js, pack.js
│   │   │
│   │   └── yandex/                 — Яндекс Маркет: заказы, ярлыки, каталог; возвраты площадка в панель не отдаёт
│   │       ├── __init__.py  client.py  store.py  sync.py  pack.py  routes.py
│   │       ├── catalog.py          — каталог одним методом (offer-mappings): ключ товара — артикул продавца
│   │       ├── templates/          — orders.html, pack_gate
│   │       └── static/             — orders.js, pack.js
│   │
│   ├── routes/                     — разделы, общие для всех площадок
│   │   ├── auth.py                 — вход, выход, переключение кабинета
│   │   ├── pack.py                 — «Сборка»: одно рабочее место на все площадки, фильтр площадок;
│   │   │                             адреса берутся из Workspace.url каждой площадки
│   │   ├── returns.py              — раздел «Возвраты»: к выдаче, лист печати, лист PDF, акты, отметки
│   │   ├── products.py             — «Товары»: общий каталог всех кабинетов, наборы, сопоставление;

│   ├── templates/                  — страницы, общие для всех площадок

│   └── static/                     — файлы, общие для всех площадок
│       ├── app.css  app.js         — стили и общие помощники (api, toast, звук, печать PDF)

│       ├── return_mark.js          — окно отметки возврата
│       ├── act_admin.js            — снятие подтверждения и удаление акта (владелец)

├── deploy/                         — установка и обслуживание сервера

│   ├── vpn-only.sh                 — закрыть панель всем, кроме подсети туннеля

│
├── data/                           — база SQLite и журналы (в репозиторий не попадает)
│
└── tests/                          — зеркало кода: общее в core/, площадки в markets/

        ├── avito/                  — заказы, сборка, этикетки
        └── yandex/                 — заказы, сборка, каталог
```

## Куда что добавлять

| Что делаете | Куда |
|---|---|
| Новая площадка | `app/markets/<код>/` + строка в `registry.py`; тесты в `tests/markets/<код>/` |
| Новый раздел для всех площадок | `app/routes/` + шаблон в `app/templates/` |
| Кусок страницы только для одной площадки | `app/markets/<код>/templates/`, подключается по имени из её объявления |
| Новая настройка, задаваемая из панели | `db.kv_*` в модуле площадки или ядра — она переживает обновление кода |
| Разовая правка таблицы в старых базах | `app/markets/<код>/migrations.py` или `db._migrate` для общих таблиц |
| Каталог товаров новой площадки | `app/markets/<код>/catalog.py`: `pages(account)` отдаёт карточки пачками, сохраняет их ядро |
| Новое действие над связью карточек | `app/core/product_links.py` + ручка в `app/routes/products.py` |
